# پلنر روزانهٔ فروشگاه

برنامهٔ فارسی و راست‌به‌چپ برای برنامه‌ریزی روزانهٔ فروشگاه، با تقویم شمسی.
روی کامپیوتر مغازه اجرا می‌شود، به اینترنت نیاز ندارد و اطلاعات را در یک فایل
واقعی روی دیسک نگه می‌دارد — مستقل از مرورگر.

## اجرا روی کامپیوتر مغازه

با `npm run package` پوشهٔ `release/wabko-planner` ساخته می‌شود. آن را روی
کامپیوتر مغازه بگذار و روی «اجرای پلنر.bat» دابل‌کلیک کن. سرور محلی روی
`127.0.0.1:7373` بالا می‌آید و مرورگر خودش باز می‌شود.

**ذخیره‌سازی:** هر تغییر با نیم ثانیه تأخیر در `data.json` کنار همان پوشه نوشته
می‌شود. نوشتن اتمی است (فایل موقت و سپس جابه‌جایی) تا قطع برق وسط ذخیره فایل
را خراب نکند، و روزی یک نسخهٔ پشتیبان در `backups/` نگه داشته می‌شود. پاک کردن
اطلاعات مرورگر یا عوض کردن مرورگر هیچ اثری روی داده‌ها ندارد و هر مرورگری که
این آدرس را باز کند همان اطلاعات را می‌بیند.

برنامه اگر سرور محلی پیدا نکند (مثلاً روی GitHub Pages یا به‌صورت فایل تکی)
خودکار به حافظهٔ مرورگر برمی‌گردد و همین را در پایین صفحه اعلام می‌کند.

## بخش‌ها

| بخش | چه کاری می‌کند |
| --- | --- |
| **داشبورد روزانه** | تمرکز اصلی روز، چک‌لیست کارها به تفکیک باز کردن / طول روز / بستن فروشگاه، درصد تکمیل روز، نمودار وضعیت هفته، عادت‌های روزانه با استریک، ثبت سریع فروش و یادداشت روز |
| **پلنر هفتگی** | هفت ستون شنبه تا جمعه با دونات درصد پیشرفت هر روز، خلاصهٔ مالی هفته و چک‌لیست کارهای هفتگی |
| **ردیاب عادت** | جدول ماهانهٔ عادت‌ها با ستون هر روز و رنگ‌بندی هفتهٔ اول تا پنجم، ردیف انجام‌شده و درصد، نمودار پیشرفت روزانه، جدول استریک فعلی و بیشترین استریک، کارهای هفتگی و ماهانه |
| **فروش و هزینه** | ثبت فروش و هزینه با دسته‌بندی، خلاصهٔ ماه (فروش، هزینه، سود خالص، بهترین روز)، نمودار فروش روزانه و تفکیک دسته‌ها |
| **کارکنان** | فهرست کارکنان، ثبت ساعت ورود، نهار و خروج، محاسبهٔ کارکرد خالص، گزارش ماهانه و کارهای سپرده‌شده به هر نفر |
| **تنظیمات** | نام فروشگاه، واحد پول، ساعت کاری، روزهای تعطیل، قالب کارهای تکرارشونده، پشتیبان‌گیری و بازیابی |

## اجرا

```bash
npm install
npm run dev      # اجرای محلی روی http://localhost:5173
npm run build    # خروجی نهایی در پوشهٔ dist
npm run preview  # پیش‌نمایش خروجی build
npm test         # تست‌های تقویم شمسی و محاسبات
```

خروجی `npm run build` یک سایت ایستا است و روی هر هاستی (از جمله زیرپوشه)
بدون سرور قابل انتشار است.

## نکته‌های طراحی

- **تقویم شمسی** در `src/lib/jalali.ts` بدون هیچ وابستگی خارجی پیاده شده
  (الگوریتم بورکوفسکی) و با تست رفت‌وبرگشتِ ۵۰۰۰ روز پیاپی راستی‌آزمایی می‌شود.
  هفته از شنبه شروع می‌شود و همهٔ تاریخ‌ها با کلید `۱۴۰۵-۰۵-۲۴` ذخیره می‌شوند.
- **کارهای تکرارشونده** به‌صورت قالب نگهداری می‌شوند. چک‌لیست هر روز همان لحظه
  از روی قالب‌ها ساخته می‌شود و تا وقتی دست نخورده باشد چیزی در حافظه ذخیره
  نمی‌شود؛ با اولین تیک، همان نسخه ذخیره و از قالب مستقل می‌شود، پس تغییر
  بعدی قالب‌ها روزهای گذشته را خراب نمی‌کند.
- **روزهای تعطیل** چک‌لیست خودکار نمی‌گیرند، اما کار دستی روی آن‌ها ثبت‌شدنی است.
- **استریک** از روز مرجع به عقب شمرده می‌شود و اگر امروز هنوز تیک نخورده باشد
  از دیروز شروع می‌شود، تا روزِ در جریان زنجیره را صفر نکند.
- **ذخیره‌سازی** در `localStorage` است و هنگام خواندن روی ساختار پیش‌فرض سوار
  می‌شود تا نسخه‌های قدیمی داده خطا ندهند. پشتیبان‌گیری به‌صورت فایل JSON.
- **چاپ**: صفحه استایل چاپ دارد؛ با `Ctrl+P` دکمه‌ها و فرم‌ها حذف می‌شوند.

## ساختار

```
src/
  lib/        تقویم شمسی، مدل داده، محاسبات، ذخیره‌سازی و تست‌ها
  state/      کانتکست اصلی برنامه و همهٔ اکشن‌ها
  components/ دونات، نمودار میله‌ای، نوار پیشرفت و انتخابگر تاریخ
  pages/      شش صفحهٔ اصلی
  styles.css  طرح راست‌به‌چپ با پشتیبانی از حالت تاریک
```

## کارکنان و ساعت کار

- افزودن کارمند با نام، سِمت و شماره تماس؛ کارمند غیرفعال از جدول‌ها کنار می‌رود ولی سابقه‌اش می‌ماند.
- ثبت چهار ساعت در هر روز: ورود، رفتن به نهار، برگشت از نهار، خروج. کارکرد خالص خودکار
  حساب می‌شود (از ورود تا خروج منهای نهار). دکمهٔ «شیفت کامل» ورود و خروج را با ساعت
  کاری فروشگاه پر می‌کند.
- **ساعت کاری فروشگاه** در تنظیمات مشخص می‌شود (پیش‌فرض ۰۹:۰۰ تا ۲۱:۰۰) و مبنای اعتبارسنجی
  است: ساعت خروجی که قبل از ورود باشد به‌جای تبدیل شدن به یک شیفت ۲۴ساعته، به‌عنوان
  اشتباه علامت می‌خورد و از محاسبه کنار می‌رود؛ ساعت‌های بیرون از بازهٔ کاری هم هشدار
  می‌گیرند ولی محاسبه می‌شوند (اضافه‌کاری). فقط اگر ساعت بسته شدن بعد از نیمه‌شب باشد
  (مثلاً ۱۶:۰۰ تا ۰۲:۰۰) شیفت‌های گذرنده از نیمه‌شب پذیرفته می‌شوند.
- گزارش ماهانه برای هر نفر و برای کل فروشگاه: روزهای حضور، میانگین ساعت ورود، رفتن به
  نهار، برگشت از نهار و خروج، میانگین مدت نهار، میانگین ساعت کار روزانه و مجموع کارکرد ماه.
  میانگین ساعت‌ها نسبت به ساعت ورودِ همان روز محاسبه می‌شود تا در فروشگاه شبانه، خروجِ
  ۰۱:۰۰ ادامهٔ همان شیفت خوانده شود نه اول صبح.
- هر کار روزانه می‌تواند به یک کارمند سپرده شود و پیشرفتش در جدول حضور و غیاب دیده می‌شود.
- فیلد ساعت ۲۴ساعته و با ارقام فارسی است؛ کافی است چهار رقم را پشت سر هم بزنی (مثلاً ۰۹۳۰).

## انتشار روی GitHub Pages

با هر پوش، ورک‌فلوی `.github/workflows/deploy.yml` تست‌ها را اجرا و خروجی را منتشر می‌کند.
برای فعال‌سازی یک‌بار در **Settings → Pages** گزینهٔ **Source** را روی **GitHub Actions** بگذار.
